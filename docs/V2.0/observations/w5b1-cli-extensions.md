# W5B.1 CLI Extensions

Five small CLI surface improvements landed on top of the v2.0.0 baseline.
Scope: shared global flags decorator, additive `partial` stage status,
typed `Logger.emit` replacing free form events, harvest `--dry-run`,
harvest top findings table. No regressions: parity test 3/3, TS error
count steady at 0, all four smoke checks green.

## 1. Global flags plugin

New file: `engine/cli/global-flags.ts`. Exports `withGlobalFlags(cmd)`
which merges a shared args fragment into any leaf citty command, and
`readGlobalFlags(args)` / `applyGlobalFlagEnv(flags)` for the run
handler. Six flags consistently available on every subcommand:

| Flag | Effect |
|------|--------|
| `--quiet` | Suppresses info, metric, and event stdout. Errors still print to stderr. |
| `--verbose` | Forces full output even alongside `--quiet`. Sets `DEBUG=1`. |
| `--json` | Switches Logger output from human format to one JSON object per line on stdout. |
| `--no-color` | Sets `NO_COLOR=1` for downstream libs. |
| `--run-id <id>` | Override the autogenerated run id (already accepted by `createRunContext`; now exposed at the CLI). |
| `--config <path>` | Reserved for an alternate config file. Plumbed through but not yet consumed. |

### Subcommands wired

| Subcommand | Wired |
|------------|-------|
| `clone` | yes (passes quiet, verbose, json, run-id through `runParityClone` to `createRunContext`) |
| `capture` | yes (stub gated on `!flags.quiet`) |
| `parse` | yes (stub gated on `!flags.quiet`) |
| `clone-static` | yes (stub gated on `!flags.quiet`) |
| `targets list` | yes |
| `runs list` | yes |
| `runs harvest` | yes |
| `test` | yes |
| `version` | yes (`--json` emits `{"version": "..."}`) |

Help text confirmed for `parity clone --help` and `parity runs harvest
--help`; every leaf shows the six shared flags ahead of its own args.

## 2. StageStatus migration

`StageStatus` and `RunStatus` extended additively to include `partial`.
Manifest `schemaVersion` stays at 1 because readers tolerate unknown
status values for human display (uppercased, no switch).

| File | Change |
|------|--------|
| `engine/cli/stage.ts` | Union widened, new `partial(output, partialCount, totalCount, ...)` helper added alongside `ok`, `warn`, `fail`. Helper records `partial_count` and `total_count` metrics so SUMMARY.md tables show the slash count without callers remembering the keys. |
| `engine/cli/run-manifest.ts` | RunStatus and StageStatus widened. |
| `engine/cli/event-stream.ts` | `stage_end.status` and `run_end.status` widened. |
| `engine/cli/orchestrate.ts` | Pipeline rollup handles partial: it is stronger than warn, weaker than fail. Pipeline keeps going on partial so the next stage runs against the partial output. |
| `engine/cli/run-clone-stage.ts` | Phase status rollup widened via a cast; reads any phase reporting partial and promotes the run status. `ParityCloneResult.status` widened to the same union. |

`scripts/run-clone.ts` keeps its narrower local `'ok' | 'warn' | 'fail'`
phase status type (W5B.2 territory, untouched). The cast in run-clone-
stage absorbs the gap until that file adopts partial.

## 3. Logger.emit migration

`Logger.event(name, fields)` removed. Replaced by
`Logger.emit(event: PipelineEvent)`. The discriminated union from
`event-stream.ts` enforces required fields at compile time, so the
JSONL writer cannot silently drop them.

Call sites migrated: **5** (all in `engine/cli/orchestrate.ts`). Sample
before / after:

Before:
```ts
ctx.logger.event("stage_start", {
  pipeline: pipelineName,
  stage: stage.name,
  runId: ctx.runId,
});
if (hasEmit(ctx)) {
  ctx.emit({ type: "stage_start", stage: stage.name, at: nowIso() });
}
```

After:
```ts
ctx.logger.emit({
  type: "stage_start",
  stage: stage.name,
  at: nowIso(),
});
```

The redundant double post (free form `logger.event` plus typed
`ctx.emit`) collapses to a single typed call. `pipeline_start` and
`pipeline_end` have no dedicated PipelineEvent members; they are now
emitted as typed `log` entries with the metadata in `meta`.

The Logger implementation in `engine/cli/context.ts` (`rootLogger` and
`forStage`) gained an `emit(event)` method on both code paths. The
root logger writes stdout (gated by `quiet`) and the JSONL stream;
`forStage` additionally writes the per stage log file. Removed the
old `event(name, fields)` from both implementations.

## 4. Harvest --dry-run

Adds `dryRun?: boolean` to `HarvestOptions` and `--dry-run` to the
`parity runs harvest` CLI. When set, the harvester walks runs and
computes findings but skips the `fs.mkdir`, `upsertTicket`, and
`writeIndex` calls. The returned `HarvestResult` still lists the would
be ticket paths so callers can preview the plan.

Sample output:

```
$ npx parity runs harvest --dry-run
parity runs harvest finished (dry run, no files written):
  runs scanned: 2
  findings    : 0
  tickets     : 0
  index       : /Users/cameronmcallister/Github/dr-parity/docs/parity-issues/INDEX.md
```

Replaces the previous workaround of pointing `--tickets-dir=<tmp>` at a
throwaway directory.

## 5. Harvest top-N findings table

New file: `engine/cli/harvest-top-table.ts`. Exports
`renderTopFindingsTable(findings, topN)` which sorts by severity (P1
first) then surface count descending and renders a fixed width ASCII
table. Empty findings list returns an empty string so callers do not
print a stray header.

Wired into `runs-harvest-cli.ts`. Configurable via `--top=<n>` default
10. The full ticket markdown files still get written by `harvestRuns`;
the table is purely a discoverability win on the terminal.

Sample with a synthetic dataset (4 findings, top 3 shown):

```
Top findings (showing top 3 of 4):
+--------------------------------------+-----+-------+--------------------+
| slug                                 | sev | count | type               |
+--------------------------------------+-----+-------+--------------------+
| react-css-drift                      | P1  | 8     | recurring-warning  |
| astro-emit-skip                      | P1  | 3     | repeat-error       |
| duration-drift-clone                 | P2  | 4     | duration-drift     |
+--------------------------------------+-----+-------+--------------------+
```

On this repo the harvest currently finds zero issues, so the table is
not printed in the smoke test. Synthetic test confirms sort and
clamping behaviour.

## Anomalies and Surprises

- **Citty `defineCommand` strict generic.** The first cut of
  `withGlobalFlags` was typed `<T extends CommandDef<any>>(cmd: T): T`.
  TypeScript rejected that at every call site because citty's
  `CommandDef<T extends ArgsDef>` argues that the merged args type
  (extra global keys) is not a subtype of the original `T`. Fix:
  widen the return type to `CommandDef<ArgsDef>`. The caller never
  reads the args generic; the parsed args go through
  `readGlobalFlags(args as Record<string, unknown>)`.
- **`logger.event` was double posting.** Orchestrate.ts called both
  `ctx.logger.event(...)` (stdout only) and `ctx.emit(...)` (JSONL
  only) for every stage_start / stage_end. The migration collapses
  this to a single typed `logger.emit(...)` that writes both surfaces.
  The free form stdout output now carries the full JSON of the event
  for parity with the JSONL line.
- **`pipeline_start` / `pipeline_end` are not in the locked union.**
  The audit specifically locked `run_start` / `run_end` and per stage
  events; pipeline lifecycle was free form. Migrated as typed `log`
  entries with the descriptive name in `message` and the structured
  data in `meta`. No schema bump because `log` is already part of the
  union.
- **scripts/run-clone.ts phase status union.** Stayed narrower than
  the new `StageStatus`. The cast in `run-clone-stage.ts` absorbs the
  gap until W5B.2 catches up. Documented inline.
